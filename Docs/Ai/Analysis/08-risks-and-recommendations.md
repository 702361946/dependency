# 风险与改进建议

## 高优先级

### 1. 内部导入依赖 `sys.path` 修改

各 `_get_package.py` 重复修改全局路径并导入顶层 `_foundation`，其他模块再导入顶层 `modules._error_handling`。这会受安装方式、工作目录和导入器影响。

建议改为标准相对导入，例如 `from ..._foundation import Log` 和 `from .._error_handling import ReturnValue`，并添加 `dependency/modules/__init__.py`。

### 2. 构建产物与源码配置不一致

仓库内 `1.2.4` wheel 早于当前配置，Python 版本声明不一致。CI 只构建，不验证安装。

建议在干净目录重建，安装 wheel 后执行全部公共导入与最小功能测试。

### 3. 基础 JSON 读取路径错误

`_foundation.Json.load()` 可能打开 `name.json.json`。顶层 `dependency.Json` 正是该实现，但现有测试只覆盖另一个同名类。

建议修复后为顶层 API 添加回归测试，并决定保留哪一个 JSON 实现。

### 4. SQL 字符串拼接

SQLite 模块对值部分使用参数化，但表名、列名、条件、视图、触发器和数据库路径大量直接拼接。外部输入可导致 SQL 注入或语法破坏。

建议限制标识符格式，并将条件构建改成结构化参数。

## 中优先级

### 5. 返回错误模型不统一

同一项目同时使用异常、`False`、`ReturnValue` 和 `MEH`。部分失败还会把另一个结果对象嵌套到 `v` 中。

建议为公共 API 选择一种主模型，并明确哪些编程错误继续抛异常。

### 6. 导入和构造副作用

模块级日志器会创建或清空日志文件，Pygame 类构造会初始化子系统。测试和库嵌入场景难以隔离。

建议延迟初始化，并允许注入无文件日志器和后端适配器。

### 7. 测试覆盖偏斜

62 个通过测试集中在文件操作和 MEH，其他模块没有自动测试，CI 也不运行测试。

建议先覆盖基础层、SQLite 和 QR，再处理 GUI/媒体模块。

### 8. PySide6 单文件过大

`_ui_control_handling.py` 约 1745 行，包含多类控件的重复 getter/setter。

建议按文本、数值、日期时间、滑动控件和快捷键拆分，并提取共同调用模板。

## 低优先级

- 统一 `_QR`、`_SQLite3` 等模块命名。
- 统一参数名称与类型标注。
- 修正 `__varsion__`、`bilt`、`frame_rige` 等拼写。
- 更新根 README，补充 extras 和实际导入路径。
- 将 `mypy_path` 改成相对路径，并在开发依赖中声明质量工具。

## 推荐实施顺序

1. 修复包结构和相对导入。
2. 建立安装后烟雾测试并加入 CI。
3. 修复基础 JSON 与版本来源。
4. 统一错误返回协议。
5. 增加 SQLite、QR、基础层测试。
6. 拆分 PySide6 大文件。
7. 再逐步调整公共命名，必要时提供兼容别名。
